## 方法与范围

由独立评估 Agent 读取 Skill 和原始场景，逐案生成下一条完整回复；未提供预期答案或修复建议。主 Agent 审阅实际回复及卡片，按可观察行为判断，不要求固定措辞。

首轮完成 A–K 共 11 案，G 的跨会话交接存在一处目的地改写问题；作定点修正后复测 G，并新增 L 检查 v0.1 认知卡兼容。以下 12 个场景的最终观察均满足对应检查项；这不是 12 次完整长访谈或自动化端到端测试。

## 发现与修正

G 首轮生成的交接提示将交付位置写成“本次实施所在的当前对话”，会把原访谈会话改成接手会话。

只在 `references/task-card.md` 补充相对目的地的交接规则：保留原会话；有标识则带上，没有则待定位，不自动迁移。复测输出明确：

> 原规格中的“当前对话”指用户完成 r3 确认的原访谈会话，当前材料未提供其可用标识，不能默认改成接手助手所在的对话。

L 输出将“更在意工作边界”继续标为待检验假设，再问具体例外，没有将暂定解释升级为结论。

## 静态验证与限制

仓库和安装副本均通过 Skill 格式验证；界面短说明为 28 个字符，启动提示包含 `$deep-interview`。11 个 Markdown 文件中的 17 处本地引用全部可解析，差异格式检查通过；本机安装的 7 个运行时文件与仓库逐字节一致。

全部案例为虚构、无外部动作的文本测试，没有访问示例来源、创建定时任务或发送消息。未测试真实新闻筛选质量、调度准时性、其他 Agent 的安装兼容性，以及不同模型和长访谈下的稳定性；这些需要在实际宿主环境中另行验证。
